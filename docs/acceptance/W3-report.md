## 四、增量渲染（防抖动硬约束）

滚动前后对同一节点做引用对比：

```
滚动前  same=true        节点文本「我时常切慕你」
滚动后  sameNode=true    仍在 DOM 中，父节点未变
```

**未重建 DOM**。高亮走的是切 class 路径，不是 `replaceChildren()`。
否则会形成「滚动→改状态→重渲染→扰动 scrollTop→再触发 scroll」的死循环。

## 五、滚动时的 dispatch 频率

连续滚动 2 秒（每 16ms 推进 40px）：

```
highlight dispatch 次数：1
```

不是每帧一次，节流有效。开发自测报的是 125 次 scroll 事件 → 1 次 dispatch，与实测一致。

## 十、两处类型妥协（开发的主动说明，PM 判断）

### 1. `AppAction = Action | HighlightAction`

开发未把 `highlight` 并入 `Action`，理由是现有 `keyboard.test.ts` 对 `Action` 做无 `default` 的穷尽 switch，并入会触发 TS2366，而测试文件不允许改。

**判断：可接受。** `Action` 是 `AppAction` 的子集，现有调用点不破坏；`dispatch` 签名放宽不产生不安全行为。

### 2. `currentVerse?: number | null`、`hideCurrent?: boolean`（可选字段）

理由是为了不打破现有测试对初始状态键集合、样式对象精确全等的断言。

**判断：功能安全，但有技术债。**

- 所有读取处（`passage.ts:72`、`keymap.ts:23/59/68`）都显式处理了 `undefined`，没有裸用，运行时无隐患
- `DEFAULT_STYLE` 里写成 `hideCurrent: undefined` 是冗余写法（与缺省等价），仅为对齐断言

**代价**：`keymap.ts:59-62` 与 `67-72` 为兼容"旧状态快照"保留了**旧翻节语义**——也就是 P0 的破坏性写法：

```ts
if (state.currentVerse === undefined) {
  const verse = sel.verses.from + 1
  return verseSelect({ ...sel, verses: { from: verse, to: verse } })  // 压缩选区
}
```

该分支要求"有 selection 但无 currentVerse"，而 `select` 分支总会设置 `currentVerse`（`store.ts:182`），初始状态又没有 selection（被 `!sel` 提前拦下），因此**实际不可达**。实测也未触发。

**但这是休眠的 P0**：将来任何人重构掉 `currentVerse` 字段，破坏性逻辑会立刻复活。

## 十一、建议（不阻塞验收）

1. **清理休眠 P0**：删掉 `keymap.ts` 里 `currentVerse === undefined` 的两个分支，改为必填字段
2. 为此需要修 3–4 处对初始状态做精确全等的测试——**这类改动 PM 可批准**，测试断言不应成为产品类型安全的阻力
