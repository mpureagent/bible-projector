# W3 补充修复：轻点一次即点亮

日期：2026-11-03
触发：用户实测反馈「高亮单击，不要双击高亮」。

## 现象

手机上点某一节，第一次点**没有任何反应**，必须再点一次（或用双击）才点亮。

## 两个叠加的原因

### 1. 拖动留下的抑制标志无人消费（主因）

`ScrollController` 为「拖完松手不算点击」设了 `suppressClick`：

```ts
private onPointerUp = () => {
  if (moved) this.suppressClick = true   // 拖动结束置位
}
consumeClickSuppressed() {                // 等一次 click 来消费
  const value = this.suppressClick
  this.suppressClick = false
  return value
}
```

设计假设是「拖完浏览器会发一次 click，把它吃掉」。但**触摸滚动根本不产生 click**——浏览器判定手势是滚动，不是轻点。于是标志一直挂着，被用户**下一次真正的轻点**消费掉。

结果：每次滚动之后，第一下点击必然无效。用户读经时一直在滚，所以几乎每次点击都要点两次。

**修**：

- `pointerdown` 时作废上一次手势的抑制（新手势开始，旧手势的尾随 click 早该到未到）
- 抑制加 400ms 时间窗（`CLICK_SUPPRESS_MS`），过期自动失效——防止任何路径下标志长期残留

### 2. 行末空白点不中

经文是**行内 span**（自然段落连续流）。inline 元素的 `getBoundingClientRect()` 返回**跨行合并的包围盒**，盒内包含大量不属于该元素的区域：行末空白、行间隙。点在那里时 `event.target` 是父级 `<p class="flow">`，`closest('[data-verse]')` 返回 null，点击被当作"没点到经文"丢弃。

手指导航比鼠标粗得多，点空白是常态。

**修**：新增 `src/projection/hit-test.ts`，命中解析改为两级：

1. 精确命中（元素自身/祖先在 `[data-verse]` 内）
2. 落在节号上标 `.vnum` → 取其**后继兄弟**（sup 与 vtext 是兄弟，不在其内部）
3. 否则按**行矩形就近**：`getClientRects()` 给出每行一个矩形，先按垂直距离锁定"哪一行"，再在该行内按水平距离选节

即：**点哪一行，就点亮那一行上的节**；点行内越靠右，越趋向该行末尾那个节。

> 走过一段弯路：最初用 `caretRangeFromPoint` 兜底，它能穿透空白但没有"行"的概念。
> 实测点第 3 节的行末空白，caret 取到最近字符=第 2 节末字，点亮了第 2 节。故弃用。

### 3. 双指之外的缩放

投影页 `#stage` 补 `touch-action: manipulation`：去掉双击缩放，保留滚动与双指捏合。
双击缩放会毁掉投屏画面，且与"轻点即点亮"冲突。

### 4. 控制窗预览同步

预览原先也是裸 `closest('[data-verse]')`，同样点空无效。改为复用同一套命中解析，保证预览与投影手感一致。

## 验证

| 项 | 结果 |
|---|---|
| 单元测试 | **374 全绿**（新增 hit-test 17 个、抑制回归 2 个） |
| 手机「滚动后轻点行末空白」 | 连续三轮：9→3、3→5、5→3，**全部一次生效** |
| 桌面鼠标点行末空白 | 同一行依次点：3、5、7、9 全部命中 |
| 触摸拖动滚动 | 仍正常（0→992px） |
| 拖动松手 | 不误点亮为手指位置；高亮=滚动停下后的顶部第一行（符合设计） |
| 点标题/页边 | 不改变高亮 |
| 选中文本后点击 | 不改变高亮（复制摘录场景保留） |
| 两端构建 | Electron 通过、两入口 CSP 各 1 处；Web 通过 |

## 一个已知的模糊点（非缺陷）

点落在**两行之间的缝隙**且左右跨越多节时，无唯一答案。实测样例：y=257 处上行属第 2 节、下行属第 4 节，判定为上行第 2 节。

这是"最近行"的自然结果，不是错误。真实使用中用户点的是字或行末空白，不会去点 3 像素的缝。

## 教训

**抑制类标志必须有时间窗或明确的失效时机。** 依赖"下一个事件来消费"的写法，在事件不发（触摸滚动没有 click）时会静默地吃掉后面无关的用户操作。表现是"第一次没反应"，而且没有任何报错可循。
