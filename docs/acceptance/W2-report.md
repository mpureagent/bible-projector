## 三、隐藏方式：确认没有重蹈 hymn 覆辙

手机 list 态实测：

```
#left-panel    display: block   width 366   hidden=false
#right-panel   display: none    width 0     hidden=true
```

预览面板是**靠 `hidden` 属性**隐藏的，`display:none` 来自 `[hidden] { display: none !important; }` 这条通用规则。元素始终留在 DOM，移除属性即恢复。

这与 hymn-manager T10 的病根有本质区别——那边是 CSS 媒体查询里**硬编码** `.preview-pane { display: none }`，怎么写属性都救不回来。

全文 `display: none` 共 2 处：`[hidden]` 通用规则 1 处，`#banner`（提示条默认隐藏，`.visible` 时显示）1 处。**无一处砍面板。**

## 十、发现的一个非 W2 问题（记录，不在本次修复范围）

测试时发现：**深色主题 + 浅色纹理背景**的组合（如「深墨绿」主题配「米白宣纸」纹理）会导致正文文字几乎不可读。

量化（实测计算样式）：

```
文字色          rgb(216, 232, 212)   淡绿白（按深色背景设计的主题前景色）
舞台底色        rgb(15, 31, 24)      深墨绿
背景图          /textures/rice-paper.svg   浅米色（cover 铺满，盖住底色）
文字/实际背景对比度  ≈ 1.13 : 1
```

WCAG AA 要求正文 **≥4.5:1**。1.13:1 基本等于看不见。

根因：`applyStageStyle()` 在 `backgroundMode=texture` 时用纹理图 `cover` 铺满，覆盖了主题的深色 `backgroundColor`；但文字颜色仍取自深色主题（浅色字）。主题与纹理是自由组合，没有一致性约束。

**这个问题在 Electron 版同样存在**，并非 W2 引入——W2 没有触碰 `passage.ts`。属于样式系统的预设约束缺陷，不影响本工单验收。

建议后续单独评估（不在本次范围）：

1. 切到纹理/图片背景时，自动把文字色收敛为对比度安全的深色
2. 或在纹理模式下禁用深色主题
3. 或为纹理标注明暗属性，只允许与同明暗的主题搭配
