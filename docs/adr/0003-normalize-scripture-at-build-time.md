# 构建期归一化经文文本（删除 U+3000 敬空格），检索另建折叠索引

实测 `data/cuv-simplified.db`：4104 个 U+3000 全角空格分布在 3573 节里，几乎全部紧邻"神"字之前（和合本传统的敬空格排版），另有 12 个制表符、2 个 CR、37 个半角空格、42 个当省略号用的 ASCII 句点、82 行空经文。这些字符让"照原样显示"和"能搜到"无法同时成立：实测以 `起初神创造天地` 检索原始文本命中 0 条，归一化后命中 1 条（创 1:1）。我们决定在 `scripts/build-data.mjs` 里做一次归一化（规则 N1–N6，见方案 §3.1），产物同时作为**显示文本**与**检索折叠索引**的唯一来源，运行期不再做任何文本清洗。

## Considered Options

- **构建期归一化 + 折叠索引（采用）**：一次处理、发布产物即为最终形态，显示与检索共用同一份字符串，不会出现"看得到搜不到"。
- **原样保留全部字符**：否决。跨敬空格的关键字检索直接失败（实测 0 命中），且制表符/CR 会在投影排版里产生不可预测的空洞（申 32:20 是 `\r` + 20 个空格，诗 105:17 是 5 个制表符）。
- **U+3000 → 半角空格**：否决。在 60–120px 的投影字号下，半角空格仍是一个明显的洞，且 300 处位于节首会变成"每节开头莫名缩进"。
- **运行期归一化**：否决。每次启动重复处理 3.6k 节，且控制窗/投影窗两侧一旦实现不一致就会出现显示与检索分叉。

## Consequences

- **发布产物与源库不再逐字节相同**：3589 / 31103 节文本被改写，共删除 4182 个字符（1,069,107 → 1,064,925）。任何人拿 `bible.json` 与 `.db` 做 diff 都会看到差异，这是刻意的。
- **敬空格被删掉是排版取舍，不是删字**：不丢任何一个汉字。若教会坚持保留和合本的敬空格，改 `build-data.mjs` 里一个常量重新构建即可（数据是构建产物，不是源），但必须同时把 U+3000 加回字体子集。
- **字体子集必须按归一化后的字符集生成**：实测 3038 个不同字符（3005 汉字 + 33 个非汉字，含 6 处雅歌的 〔〕、596 个 `·`、48 个数字），加书卷名/拼音共 3062 字；其中 769 个字出现 ≤6 次，**不能按词频裁剪**，否则冷僻字在投影上变豆腐块。
- **只发布 text-only JSON**：折叠索引在启动期现算实测 38.9ms（开发机 Node 26，31103 节），可忽略；因此产物取 3.22MB 的纯文本版，而不是 5.97MB 的"文本 + 索引"双份版。
- **82 行空经文必须保留行号**（编号与纸质和合本对齐），但显示与检索都要跳过；其中 13 行是"有古卷无此节"的正常占位，69 行是上一节并节，8 行并节后上一节以逗号/分号结尾（疑有文字缺失，已列入 M4 人工核对清单）。
- **归一化规则一旦上线就绑住了搜索行为**：改规则等于改用户能搜到什么，因此 N1–N6 必须有单测覆盖（§10 第一层），不能只靠肉眼验收。
