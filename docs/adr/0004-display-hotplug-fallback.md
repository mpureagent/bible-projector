# 投影窗显示器热插拔：回退主屏 + 按 display id 自动重连

现场讲道中 HDMI 线松动或电视被切走输入源，Electron 的 `display-removed` 会带走目标显示器，投影窗销毁或挂到未知屏——这是投屏软件最伤的事故形态（全场看不见经文）。我们决定在 `windows.ts` 里实现三态状态机（ASSIGNED → FALLBACK → PENDING_RECONNECT）：display 断开时投影窗**立即回退主屏全屏且画面内容不断档**，display 重连时按持久化的 `display.id` **自动**迁回原屏；id 不匹配（换了电视）则停主屏由操作员一键改选。方案细节见 technical-plan §3.3。

## Considered Options

- **回退主屏全屏 + 按 id 自动重连（采用）**：事故瞬间仍有画面（主屏就是操作员面前的显示器或第二块可用屏），重插 HDMI 后零操作恢复；同一线缆重插通常保持同一 `display.id`，自动重连命中率最高。
- **回退后仅手动恢复（一键改选）**：否决为主策略。多数事故就是"线松了重插一下"，还要人手点一次恢复是把成本转嫁给最忙的操作员；但保留为 id 不匹配时的兜底路径。
- **保持投影窗挂在已消失的 display 上等待**：否决。窗口进入不可见状态，现场表现为"黑屏且不知道怎么了"，且部分平台上窗口会被系统强制移动/缩放，行为不可控。
- **按 display index 指派**：否决。热插拔后 index 漂移（拔掉副屏会让主屏 index 变化），恢复会指错屏——必须按 `id`。
- **自动重连 + 自动扫描所有新 display 迁窗**：否决。换了电视时自动迁到新屏可能指到讲台监控器等错误目标，指错比停主屏更糟。

## Consequences

- **`AppState.display` 持久化的是 id**，启动时按 id 查找目标 display；查不到（上次关机时副屏就没接）直接进 FALLBACK 并提示，不猜屏。
- **display-added 的判定逻辑必须可测**：状态迁移是纯函数（输入：当前态、事件、display 列表；输出：新态+窗口动作），单测覆盖拔线/重插/换屏/单屏四种序列（M1 建骨架时落地）。
- **回退动作要在 display-removed 事件同一轮完成**，中间不留可感知的黑屏帧；Electron 22 的 `screen` API 在事件顺序上偶发 `display-metrics-changed` 与 `display-removed` 交叠，实现须容忍乱序（以最终 display 列表为准，不信任单一事件）。
- **FALLBACK 期间顶栏常驻状态条**，操作员任何时候都知道当前投在哪块屏——静默回退（人不知情）等同事故。
- 验收标准进 §11 风险行与 M3：拔线—重插全流程不断档、不闪退；换屏一键改选迁移 ≤100ms。
