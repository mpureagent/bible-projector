# W2 · 手机端布局：让控制窗在窄屏可用

**类型**：feat　**优先级**：P0（用户主要用手机验收）　**依赖**：W1 已通过　**预估**：中等

## 一、为什么做

W1 让应用能在浏览器里跑，但界面仍是桌面双栏。用户的目标是**在手机上验收界面和样式**，所以窄屏必须能用。

## 二、实测问题（PM 量的，不是估的）

390×844 视口：

```
clientWidth        390
scrollWidth        662     ← 横向溢出 272px
预览面板宽 290px，left=372，right=662   ← 完全在屏幕外
```

现有布局是「左栏书卷列表 372px + 右侧预览 290px」硬拼，**没有任何媒体查询**。手机上只能看到书卷列表，预览、操作条、样式面板全部不可达。

## 三、目标

手机（≤900px）上做到：**能选经、能看预览、能改样式、能投屏**，横向溢出为 0。

桌面（>900px）行为**必须零变化**。

## 四、方案要求

复用 hymn-manager T10 已验证的模式：

### 4.1 两态切换，不要堆叠

窄屏下改为单栏两态：`narrowView: 'list' | 'detail'`

- `list`：书卷列表 + 搜索 + 旧约/新约/历史 Tab
- `detail`：操作条（投屏/选区标签/复制）+ 经文预览 + 「‹ 返回列表」
- 选中经文后自动进 `detail`；返回键回 `list`

**关键**：不要用 `display: none` 隐藏预览面板。hymn 项目就栽在这里——`display:none` 让歌词在手机上彻底不可见，因为面板本身被砍掉了。用 `hidden` 属性或 `narrowView` 状态驱动，元素必须留在 DOM 里。

### 4.2 必须解决的溢出

- 主体容器加 `min-width: 0` 或用 `grid-template-columns: minmax(0, 1fr)`。hymn 的根因是顶栏 min-content 把隐式网格列撑到 506px
- 顶栏内容在 390px 下不能撑破：字号/内边距要收，必要时让操作条换行
- 所有按钮触控区 ≥44px

### 4.3 级联选经弹窗

四列（书|章|起始节|结束节）在 390px 放不下。要求：

- 窄屏改成**分步**：先书 → 再章 → 再节范围，或改成一列一列下滑
- 不得横向滚动
- 关闭按钮（✕ / 遮罩）保持可用

### 4.4 样式面板

现在是右侧滑入抽屉。窄屏改为**底部抽屉**（如 `max-height: 70vh`，从下往上滑），可滚动，✕ 与遮罩关闭。hymn 的实测值可参考：宽 390、`max-height: 590.8px`（70vh）、贴底。

### 4.5 投屏在手机上

手机上没有第二块屏。要求：

- 「投屏」在窄屏下仍可用（浏览器会开新标签）
- 若同机打开，新标签是全屏投影预览，用户切过去看效果
- 提示文案不要假设"第二块屏"存在

## 五、验收标准

1. 现测试全绿（292 个），新增窄屏相关测试 ≥6 个，**不得修改现有测试**
2. 390×844：
   - `document.documentElement.scrollWidth - clientWidth = 0`
   - 初始态看得到书卷列表；点书卷能完成选经
   - 选完后预览显示经文，有「‹ 返回列表」，点它回到列表
   - 样式面板为底部抽屉，贴底、可滚动、可关闭
   - 字号调到最大（200）仍无横向溢出
3. 768×1024（平板）同样无溢出、可用
4. **桌面回归**：1440×900 与 1920×1080 下，双栏布局、栏宽、无返回按钮，行为与 W1 完全一致
5. console 零报错

## 六、明确不做

- 不为手机做专属功能（如横屏锁定、手势翻页）
- 不改共享渲染逻辑（`passage.ts` 的排版核不动）
- 不改 Electron 窗口行为
