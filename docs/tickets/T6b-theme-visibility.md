- 背景：用户 v0.9.0 真机验收追加两问题：⑥ 主题样式"没有生效"；样式面板无关闭按钮。
  PM 根因分析：⑥ 大概率是 v0.9.0 中样式广播仅达投影窗，用户在控制窗预览看不到主题变化（投影窗全屏在另一屏/被 Alt+Tab 甩开），并非样式引擎坏——T4 时 Xvfb 实测投影 background 随米白 token 变过。但"预览应实时反映投影样式"是方案 §6.2 的承诺（"与投影同样式的小比例预览"），v0.9.1 的本地阅读模式更必须做到：不投屏时，用户在控制窗里就要能看到主题/字号效果。

## 任务（每任务一 commit：T6b-preview / T6b-close）

### 任务 1：预览与投屏同源渲染（T6b-preview）
- 控制窗经文预览与投影窗使用**同一排版引擎**（src/projection/render.ts 或其纯函数核），字号按比例缩放（如 1/2 或自适应预览区宽），但**主题、字色、行距、边距、节号显隐全部跟随当前样式状态**
- 断言用例：切换墨金/米白/深蓝任一主题后，预览容器 computed style 背景色/文字色与 themes.ts token 全等；改字号/行距后预览样式同步变化（happy-dom 或 Xvfb 实测均可，方法自选，证据进测试日志）
- 若发现样式广播链路存在真 bug（非仅预览缺失），一并修复并如实记录根因

### 任务 2：样式抽屉可关闭（T6b-close）
- 抽屉右上角「✕」关闭按钮（≥32px 触区），点击=收起抽屉；`S` 键开/合语义保留（焦点在抽屉内输入框时 S 不误触发——沿用 keyboard.ts 输入框不劫持规则，补一条断言）
- 点击抽屉外区域是否关闭：实现者按主流交互定（建议：遮罩点击关闭），写入测试
- E2E：Xvfb 截图一张（抽屉打开态，✕ 可见），点 ✕ 后收起断言
