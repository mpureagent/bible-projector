## 必改项（P0）
### P0-1 技术基线决策：单基线 Electron 22.x
- 决策：全平台统一使用 **Electron 22.x**（最后支持 Win7/8.1 的 LTS），**不做双分支**
- 理由：本 app 极简，Chromium 102 完全够用；双分支意味着双倍打包/测试/维护成本，违背"极简"
- 必须写入 ADR（用 .qoder/skills/domain-modeling 的 ADR-FORMAT）：记录该决策、被否方案（双分支/仅Win10）、风险（Electron 22 已 EOL 无安全更新——离线+管理员环境可接受；主进程 Node 16 API 边界；渲染端不可用 2022 年后新 CSS 特性）
- 相应修订：§3 技术选型表、§11 风险表（Win7 风险行从"对策"改为"基线"）、§2.4 指标（低配目标机含 Win7）

### P0-2 新增"打包管线"章节（v1 完全缺失）
当前开发机是 Linux，产物必须是 Windows 安装包。必须写清：
1. Linux 交叉构建 NSIS/portable 的可行性验证方法与结论（electron-builder 在 Linux 出 NSIS 是否需要 wine；exe 元数据 rcedit 的替代路径）
2. 若本机交叉不可行 → 备选路径（如 CI Windows runner / Windows 虚拟机内构建），写清采用哪条及原因
3. 产物验收流程：Win7 实机/VM + Win10 VM 各安装一次、断网启动一次、双显示器环境跑一次
4. 允许在本任务内写一个 spike 脚本实测第 1 点，把真实结果写进方案（不许凭记忆断言）

### P0-3 build-data 数据归一化（v1 未意识到）
实测 `cuv-simplified.db` 经文中含 **U+3000 全角空格**（如"起初，　神创造天地。"，CUV 传统排版）：
- 构建期必须做不可见字符归一化（U+3000→普通空格或删除，定一个规则并说明对显示效果的影响）
- 搜索需在该归一化文本上进行，否则关键字搜索（如"神创造天地"）匹配失败
- 拼音匹配需大小写不敏感（库中 PinYin 为大写 CSJ）
- 在 §3.1/§8 补充对应处理，并给出验证方法（用 3-5 个真实搜索词断言）

### P0-4 投影窗显示器热插拔状态机（v1 完全缺失）
现场事故场景：讲道中 HDMI 松动/电视切输入源 = 投影黑屏。
- windows.ts 设计增补：display change 事件监听 → 目标显示器断开时投影窗自动回退主屏/全屏 → 显示器重连后可一键或自动恢复指派
- 写入 §3.2 与 §11 风险表，验收标准：断开-重连全流程不断档、不闪退
