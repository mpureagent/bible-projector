## 需求原文（用户 2026-10-11）
搜索卷时可用拼音首字母：`sp`→诗篇，`mkfy`→马可福音。

## PM 实测发现的缺陷（必须解决）
源库 `BibleID.PinYin` 字段不可直接用：
- 马可福音存的是 `MK`（两字首字母），`mkfy`（全四字首字母）**查不到**
- 哥林多前书存 `GLQ`（既非全名也非简称首字母，规则不一致）
- 结论：源字段覆盖率与规则性不满足需求，方案 v1"支持拼音首字母"的声称不成立

## 技术方案要求（写入方案，作为 §2.1/§3.1 修订）
1. build-data.mjs 构建期为每卷生成**拼音首字母集合**，来源三路：
   - 全名逐字首字母（马可福音→mkfy、哥林多前书→gldqs、启示录→qsl/启tsl→按实际）
   - 简称首字母（林前→lq、启→q、诗→s）
   - 保留源库 PinYin 原值作第三路（兼容 csj 这类既有数据）
2. 汉字→首字母映射表：基于 66 卷全名+简称的字符集手工建表（预计 ≤120 字），存 `src/shared/pinyin-initials.json`，构建期确定性生成、可人工审计；不引入运行时拼音库
3. 搜索时匹配规则：输入 ≤4 字符先按首字母**前缀**匹配（mk 命中马可/马太，mkfy 命中马可福音），同时保留全名 substring 与简称匹配；结果排序：前缀精确 > 简称 > 全名包含
4. 验收断言（必须写进方案测试策略，M2 执行）：`sp`→诗篇；`mkfy`→马可福音；`mt`→马太福音；`lq`→哥林多前书；`qsl`→启示录；`gn`→约翰(案)福音 等 ≥8 例，大小写不敏感
   （注意：启示录全首字母应为 qisulu→qsl；约翰福音 yuehanfuyin→yhfy。由实现者以映射表实际生成为准，断言例须全数通过）
