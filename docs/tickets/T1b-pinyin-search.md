## 需求原文（用户两次语音/文字，第二次覆盖第一次的规则二）
1. 搜索卷名时可用拼音首字母：`sp`→诗篇，`mkfy`→马可福音
2. 单字母也算前缀：`l` 能搜出"林前"（哥林多前书），`lq` 也能
3. **【范围决定】不需要检索经文内容——搜索框只检索卷名与卷名简称。"经文关键字"功能删除**

## 对既有方案的三处修改
### A. §2.1 搜索框规格（范围收窄）
- 原规格"卷全名/简称/拼音首字母/经文关键字" → 改为"卷全名/简称/拼音首字母前缀"，**删除"经文关键字"**
- §8 中与"100万字符 indexOf 全文扫描"相关的搜索性能论述随之删除/改写（首字母匹配 trivial，无需专门性能设计）
- 历史功能（最近50条）不受影响

### B. P0-3 动机变更（继承 T1，仍必改）
- T1 任务单 P0-3 的 U+3000 全角空格归一化：动机从"保证搜索命中"改为**纯显示排版质量**（投影窗"起初，　神创造天地。"的怪缝）。处理要求不变：构建期归一化规则写入方案并给出渲染前后对比说明；大小写不敏感要求移入本节 C 的匹配规则
- 在 technical-plan v2 修订记录表中把 P0-3 标注"动机修订（T1b）"

### C. 卷名拼音索引技术方案（原 T1b 核心，保留）
源库 `BibleID.PinYin` 实测不可直接用（马可福音只存 `MK`，`mkfy` 查不到；哥林多前书存 `GLQ`，规则不一致）。要求：
1. build-data.mjs 构建期为每卷生成**首字母字符串集合**，三路来源：
   - 全名逐字首字母：马可福音→`mkfy`、哥林多前书→`gldqs`、启示录→`qsl`
   - 简称逐字首字母：林前→`lq`、诗→`s`、启→`q`、王上→`ws`
   - 保留源库 PinYin 原值兜底
2. 汉字→首字母映射表：基于 66 卷全名+简称字符集手工建表（≤120 字），存 `src/shared/pinyin-initials.json`，构建期确定性生成、可人工审计；不引入运行时拼音库
3. 匹配规则：集合内**每个字符串独立做大小写不敏感前缀匹配**（单字符也是前缀：`l` 命中 `lq`），叠加全名/简称的 substring 匹配；结果排序：前缀精确 > 简称命中 > 全名包含
4. 验收断言（写入方案测试策略，M2 执行；"命中"=结果集合包含）：
   - `s`→诗篇；`sp`→诗篇；`l`→林前；`lq`→林前；`gldqs`→林前；`mk`→马可福音；`mkfy`→马可福音；`mt`→马太福音；`yh`→约翰福音；`qsl`→启示录
   - 反向断言：输入任意经文片段（如 `爱世人`）**不产生任何结果**（经文检索不存在）
   - 实现者若修正断言例（如 qsl 实际生成规则），须给出理由且断言全数通过
